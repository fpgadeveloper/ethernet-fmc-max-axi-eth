# Troubleshooting

## Build failures

Check the following if the project fails to build or generate a bitstream:

1. **Are you using the correct version of Vivado for this version of the repository?**   
   Check the version specified in the Requirements section of the README.md file. Note that this project is regularly updated
   and you may have to refer to an earlier commit of this repo if you are using an older version of Vivado.

2. **Do you have the required licences?**   
   The AXI 1G/2.5G Ethernet Subsystem's tri-mode MAC needs the AMD Tri-Mode Ethernet MAC (TEMAC) licence
   (an evaluation licence works for testing), and most boards need the Vivado Enterprise edition. See
   [Requirements](requirements) and the IP Licence column of the target tables.

3. **Did you correctly follow the build instructions?**   
   Please check the build instructions carefully as you may have missed a step. `./build.sh status --target <target>`
   shows which stages are built.

4. **Did you copy/clone the repo into a short directory structure?**   
   Windows doesn't cope well with long directory structures, so copy/clone the repo into a short directory structure such as
   `C:\projects\`. When working in long directory structures, you can get errors relating to missing files, particularly files 
   that are normally generated by Vivado (FIFOs, etc).

## Ports not working

These checks apply to the standalone application and to both Linux flows.

1. **Is the card on the right connector?**   
   Each target is built for one FMC connector (for example `zcu102_hpc0` for HPC0, `vck190_fmcp1` for FMCP1). The
   card does not work on another connector of the same board with that target's image.

2. **Is VADJ on?**   
   The Ethernet FMC Max needs VADJ = 1.5 V. If VADJ is off, the PHYs are unpowered: the ports show no link and in Linux the PHYs may not be found on the MDIO bus. How VADJ is switched on depends
   on the board:
   * ZCU102 and ZCU106: the first-stage boot loader reads the card's EEPROM and sets VADJ.
   * **ZCU104:** the same, but only with the FSBL patch that the PetaLinux and Yocto BSPs apply; make sure you
     boot an image built from this repository.
   * Versal (VCK190, VMK180, VPK120, VPK180): the standalone application and the U-Boot of the Linux images switch VADJ
     on. If you replace U-Boot or boot Linux in another way, VADJ must be switched on before Linux starts. The VEK280
     enables VADJ by default.
   * Other boards (VADJ set by the board's system controller, power-on default or a jumper): check the board's user
     guide and make sure VADJ is 1.5 V.

3. **Is the link partner OK?**   
   Try another cable and another port on the PC or switch. Check that the partner supports auto-negotiation at the
   speed you expect; `ethtool <interface>` on the board shows what the partner advertises
   (`Link partner advertised link modes`).

4. **Linux: is the PHY found?**   
   `dmesg | grep "PHY \["` should list one `TI DP83867` PHY per FMC port, at MDIO addresses `01`, `03`, `0c` and `0f`
   of `axienet-<base of axi_ethernet_0>`. If a PHY is missing or bound to `Generic PHY`, check that the image was built
   for your target (the `port-config.dtsi` overlay describes the PHYs) and that VADJ is on.

5. **Linux: check the interface-to-port assignment for your image.**   
   The `endN` interface number does not follow the FMC port number, and the mapping differs between targets and between
   PetaLinux and Yocto. Identify ports by MAC address (`00:0a:35:00:01:22` to `…:25` for ports 0 to 3); see
   [Identify the ports](linux_testing.md#identify-the-ports).

6. **Linux: several ports on the same subnet.**   
   When several ports are on one subnet, replies can leave through a different interface than the one you are testing.
   Bind tests to an interface (`ping -I`, `iperf3 --bind-dev`) or use one subnet per port, e.g. `end3=192.168.1.10`,
   `end0=192.168.2.10`, `end1=192.168.3.10`, `end2=192.168.4.10`. See
   [Multiple ports on one network](linux_testing.md#multiple-ports-on-one-network).

### Board Ethernet port links up but passes no traffic (Yocto)

If the board's own RJ45 (PS GEM) reports `Link is Up - 1Gbps/Full` but DHCP never completes and no packets are
received, the board PHY is not described in the device tree and its RGMII clock delays are not set. The Yocto BSPs of
this repository describe the board PHY in `Yocto/bsp/<board>/meta-user/recipes-bsp/device-tree/files/system-user.dtsi`;
if you made your own BSP, copy that node. `dmesg | grep macb` should show `driver [TI DP83867]` (or `ADIN1300` on
some VEK280 revisions) rather than `Generic PHY`.

## PetaLinux issues

### Build fails with `bitbake petalinux-image-minimal failed` and sstate fetch errors

If `./build.sh petalinux --target <board>` ends with errors like:

```
ERROR: <package>-<ver>-r0 do_..._setscene: Fetcher failure: Unable to find file file://.../sstate:...
[ERROR] Command bitbake petalinux-image-minimal failed
```

the build is not actually broken. These `_setscene` errors come from bitbake
trying to pull prebuilt artifacts from the public Xilinx sstate-cache mirror,
which intermittently returns 404 for individual packages. Bitbake falls back
to building them locally and succeeds, but exits non-zero because of the
failed fetches, so the build runner stops before `petalinux-package` runs and no
`BOOT.BIN` is produced.

**Fix: re-run the same command.** The second attempt finds the missing
packages in the local sstate cache populated by the first run and completes
cleanly. This is a mirror issue, not a problem with the reference design.

## Yocto issues

### The board does not boot from the SD card (no output after power-on)

The Yocto disk image does not carry `BOOT.BIN` on its first (FAT32) partition. After writing `rootfs.wic.xz`, copy
`BOOT.BIN` onto partition 1 of the card ([Prepare the SD card](yocto.md#prepare-the-sd-card), step 4). Also check
the boot-mode switches.

### Versal: the board stops at the U-Boot prompt

On Versal the image boots Linux through systemd-boot, and the image ships an empty `EFI/BOOT/` folder. Copy
`BOOTAA64.EFI` into `EFI/BOOT/` on partition 1 of the card ([Prepare the SD card](yocto.md#prepare-the-sd-card),
step 5).

### The card is too small

The Yocto disk image is 8 GiB, which is larger than a nominal 8 GB SD card. Use a 16 GB or larger card.

### Login asks for a new password

This is expected: the EDF image requires the `amd-edf` user to set a password at first login.

## Dropped pings/packets

No dropped packets are to be expected with our example designs. If you are experiencing dropped packets of any kind, please ensure that
you have no timing errors or critical warnings in the Vivado design.

We ensure that there are no timing errors or issues on all of our designs before making a release, so typically this problem occurs on
custom designs where the timing issues have not yet been optimized. Please [contact us](https://opsero.com/contact-us/) for support 
if you are experiencing dropped packets.
